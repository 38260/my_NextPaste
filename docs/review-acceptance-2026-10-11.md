## 审阅发现

以下按个人 Windows 桌面端使用、最多 10000 条记录的既有范围审查。

### 必须修复

1. **[P1] WebView2 迁移失败后会永久跳过旧配置。**
   - 位置：`server/brand_windows.go:21-24`、`:40-43`、`:31-32`。
   - 情况：旧版仍运行、目录句柄占用或权限问题导致 `os.Rename` 失败。
   - 问题：迁移只记录错误，启动仍无条件使用新目录。WebView2 初始化新目录后，未来启动看到目标存在便不再迁移，连接配置与偏好一直留在旧目录而未被使用；原文件不被删除，但用户会表现为配置丢失。
   - 证据：用临时 AppData 和不允许 `FILE_SHARE_DELETE` 的真实 Windows 目录句柄复现。第一次迁移因占用失败，模拟新目录初始化，释放句柄并再次迁移后，旧配置标记仍未进入新目录，测试明确失败。未触碰真实用户数据。
   - 最小修复：把迁移错误返回给启动层，失败时提示并停止使用新目录，保留旧数据供后续重试；补充“目录占用后重试”和“目标已存在”的回归。
   - 不修的影响：升级遇到目录占用时，连接、自启动作、显示偏好可能长期不可恢复到界面。

2. **[P2] 连续点击同一条托盘记录，第二次定位失效。**
   - 位置：`server/frontend/src/AppInner.vue:287-290`、`server/frontend/src/components/LogViewerPanel.vue:91-102`。
   - 情况：点击某条记录，等待高亮结束，滚动到其他位置，再点击同一条记录。
   - 问题：事件只把相同 ID 赋给同一个 ref；Vue 不触发值未变化的 watcher，因此没有再次滚动和高亮。
   - 证据：真实组件浏览器测试记录 `scrollIntoView` 调用；首次调用 1 次且高亮出现，第二次同 ID 仍为 1 次且无高亮，改点另一 ID 后再点原 ID 正常触发。测试同时确认没有运行时错误。
   - 最小修复：每次 `record:focus` 都直接调用定位方法，或让触发值携带递增序号；补充同 ID 重复点击断言。
   - 不修的影响：用户需要先点另一条记录才能再次定位原记录。

3. **[P2] 自启迁移先删除旧项，写入失败时失去重试来源。**
   - 位置：`server/autostart_windows.go:105-113`。
   - 情况：旧项删除成功，但新项 `SetStringValue` 因注册表写入错误失败。
   - 问题：错误分支明确承认旧值已经删除，下一次启动已无法知道原自启状态与模式；仅记录日志不能保住状态。
   - 证据：完整调用链和错误分支静态确认；没有为制造失败而改真实注册表权限。
   - 最小修复：先成功写入新项，再删除旧项；已有新项时优先保留新配置，并覆盖写入失败/删除失败的隔离回归。
   - 不修的影响：一次写入失败可能永久关闭原自启，需用户手动恢复。

### 应当修复

4. **[P2] 旧浏览器回归漏报新接口错误，且没有覆盖新定位行为。**
   - 位置：`server/frontend/tests/clipboard-table.js:6`、`:19-24`、末尾错误断言。
   - 情况：当前组件调用新绑定 `SetContentRevealed`，但测试的 Wails Mock 没有该方法。
   - 问题：Vue 把 TypeError 写入控制台，脚本只观察 `pageerror`，最终仍可报告 PASS；这不能证明“零运行时错误”。同时缺少 `record:focus` 重复 ID 等新增事件的断言。
   - 证据：原脚本控制台明确出现 `window.go.main.App.SetContentRevealed is not a function`，CLI 仍退出成功。补齐 Mock 和控制台断言的临时副本通过既有交互回归。
   - 最小修复：更新边界 Mock，收集 JavaScript 控制台错误，新增本轮事件的必要断言。
   - 不修的影响：以后绑定或事件回归仍可能被测试掩盖。
